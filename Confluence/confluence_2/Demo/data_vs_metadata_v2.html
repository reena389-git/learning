So why bother? Feed metadata to AI — watch it write the SQL.
Live demo: I share only the metadata (not the data) with ChatGPT in M365. Ask a business question. Get a runnable query.
1
Share the metadata
I paste the YAML contracts for the two tables into ChatGPT. No actual data — just the metadata.
# star_fact_issuer_exposure schema: - name: star_fact_issuer_exposure properties: - name: counterparty_code type: STRING description: Counterparty facing TD references: star_dim_counterparty.counterparty_code - name: as_of_date type: DATE - name: issuer_type allowedValues: [Sovereign, Bank, Corporate, Supranational, Agency] - name: indirect_exposure type: DECIMAL(18,2) unit: USD aggregation: semi-additive methodology: CCR_ENGINE_v4.2 # star_dim_counterparty schema: - name: star_dim_counterparty properties: - name: counterparty_code primaryKey: true - name: regulatory_regime allowedValues: [OSFI, EMIR, SEC, CBIRC, JFSA, CFTC] - name: counterparty_rating
2
Ask a business question
In plain language. No SQL knowledge required from the asker.
Risk analyst → ChatGPT (M365) Give me the top 10 sovereign issuers by total indirect exposure across counterparties under the OSFI regulatory regime, as of the latest snapshot date.
Every concept the analyst uses — sovereign, indirect exposure, OSFI regime, latest snapshot — is grounded in the metadata.
3
ChatGPT generates the SQL
Joins the right tables on the right keys. Picks the right filter. Aggregates correctly.
SELECT f.issuer_name, SUM(f.indirect_exposure) AS total_exposure_usd FROM creditrisk.xvala_xva.star_fact_issuer_exposure f JOIN creditrisk.xvala_xva.star_dim_counterparty c ON f.counterparty_code = c.counterparty_code WHERE f.issuer_type = 'Sovereign' AND c.regulatory_regime = 'OSFI' AND f.as_of_date = ( SELECT MAX(as_of_date) FROM creditrisk.xvala_xva.star_fact_issuer_exposure ) GROUP BY f.issuer_name ORDER BY total_exposure_usd DESC LIMIT 10;
