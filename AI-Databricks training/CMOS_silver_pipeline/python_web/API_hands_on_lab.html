We build one small real thing — an Instrument Reference API serving securities data — in isolated steps. Run each step, read the output, and the words become concrete. No prior web experience assumed.

The mental model

before any code — what these pieces are

An API is a server that answers requests. A client sends a request ("give me AAPL"); the server sends back a response (the data + a status code). That back-and-forth is the whole idea.

The four libraries, in one line each

Pydantic — defines the shape of the data and validates it (the contract).

SQLAlchemy — talks to the database (define tables, read/write rows) in Python.

FastAPI — the server: maps URLs to functions, checks requests against the contract.

httpx (client) + OpenAPI (the auto-written contract/docs) — the other side, and the proof.

Pydantic — the contract

define a data shape · validate good and bad data · no web yet

Before servers or databases, just this: describe what an instrument is, and let Pydantic enforce it.

step1_pydantic.py
from pydantic import BaseModel, field_validator, ValidationError

ALLOWED = {"equity", "bond", "fx", "commodity"}

class Instrument(BaseModel):        # a "model" = a data shape
    symbol: str
    name: str
    asset_class: str
    price: float

    @field_validator("asset_class")     # a custom rule for one field
    @classmethod
    def known_class(cls, v):
        if v not in ALLOWED:
            raise ValueError(f"asset_class must be one of {sorted(ALLOWED)}")
        return v

    @field_validator("price")
    @classmethod
    def non_negative(cls, v):
        if v < 0:
            raise ValueError("price must be >= 0")
        return v

good = {"symbol": "AAPL", "name": "Apple Inc", "asset_class": "equity", "price": 195.2}
print("VALID   ->", Instrument(**good))
print("as dict ->", Instrument(**good).model_dump())

bad = {"symbol": "BAD", "name": "Nope", "asset_class": "crypto", "price": -5}
try:
    Instrument(**bad)
except ValidationError as e:
    print("REJECTED:")
    for err in e.errors():
        print("   -", err["loc"][-1], ":", err["msg"])
Run: python step1_pydantic.py
VALID -> symbol='AAPL' name='Apple Inc' asset_class='equity' price=195.2 as dict -> {'symbol': 'AAPL', 'name': 'Apple Inc', 'asset_class': 'equity', 'price': 195.2} REJECTED: - asset_class : Value error, asset_class must be one of ['bond', 'commodity', 'equity', 'fx'] - price : Value error, price must be >= 0
What just happenedYou declared field types (str, float) and two rules. Pydantic parsed the good dict into an object and rejected the bad one with clear reasons. This exact model becomes your API's request/response contract later — same code, reused.

SQLAlchemy — the database

define a table · write rows · read them back · still no web
step2_sqlalchemy.py
from sqlalchemy import create_engine, String, Float, select
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, Session

engine = create_engine("sqlite:///demo.db")     # a local file database

class Base(DeclarativeBase):
    pass

class Instrument(Base):                          # one class == one table
    __tablename__ = "instruments"
    id:          Mapped[int]   = mapped_column(primary_key=True)
    symbol:      Mapped[str]   = mapped_column(String, unique=True)
    name:        Mapped[str]   = mapped_column(String)
    asset_class: Mapped[str]   = mapped_column(String)
    price:       Mapped[float] = mapped_column(Float)

Base.metadata.create_all(engine)                 # CREATE TABLE if needed

with Session(engine) as s:                        # WRITE two rows
    s.add(Instrument(symbol="AAPL", name="Apple Inc", asset_class="equity", price=195.2))
    s.add(Instrument(symbol="UST10Y", name="US Treasury 10Y", asset_class="bond", price=98.7))
    s.commit()

with Session(engine) as s:                        # READ them back
    for r in s.scalars(select(Instrument)).all():
        print(f"{r.id}: {r.symbol:8} {r.asset_class:8} {r.price}")
    one = s.scalar(select(Instrument).where(Instrument.symbol == "AAPL"))
    print("looked up AAPL ->", one.name)
Run: python step2_sqlalchemy.py  (creates demo.db in the folder)
1: AAPL equity 195.2 2: UST10Y bond 98.7 looked up AAPL -> Apple Inc
What just happenedA Python class became a SQL table. Session is your workspace for a unit of work — add + commit to write, select to read. You never wrote raw SQL. This is the storage the server will read from.

The smallest possible server

one endpoint · see request → response for real
step3_server.py
from fastapi import FastAPI

app = FastAPI()

@app.get("/ping")            # when a GET request hits /ping, run this function
def ping():
    return {"status": "ok"}   # returned as JSON, with a 200 status code
Run the server: uvicorn step3_server:app --reload
Then, in another terminal (or a browser): curl http://127.0.0.1:8000/ping
{"status":"ok"}
The one new idea: a route@app.get("/ping") is a decorator — it says "wire this URL + method to this function." That mapping (method + path → function) is the core of every API. uvicorn is the process that runs it and listens on port 8000.

Put it together — serve the database, shaped by the contract

FastAPI + SQLAlchemy + Pydantic in one file · GET endpoints

This is app.py — the real thing. It has all three layers. Read the four numbered blocks; they're the three libraries plus the wiring.

app.py
from fastapi import FastAPI, HTTPException, Depends
from pydantic import BaseModel, field_validator, ConfigDict
from sqlalchemy import create_engine, String, Float, select
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, Session

# ---- 1. SQLAlchemy: the DATABASE ----
engine = create_engine("sqlite:///instruments.db")
class Base(DeclarativeBase): pass
class InstrumentRow(Base):
    __tablename__ = "instruments"
    id:          Mapped[int]   = mapped_column(primary_key=True)
    symbol:      Mapped[str]   = mapped_column(String, unique=True)
    name:        Mapped[str]   = mapped_column(String)
    asset_class: Mapped[str]   = mapped_column(String)
    currency:    Mapped[str]   = mapped_column(String)
    price:       Mapped[float] = mapped_column(Float)
Base.metadata.create_all(engine)

# ---- 2. Pydantic: the CONTRACTS ----
ALLOWED = {"equity", "bond", "fx", "commodity"}
class InstrumentIn(BaseModel):        # what a client SENDS (no id)
    symbol: str; name: str; asset_class: str; currency: str; price: float
    @field_validator("asset_class")
    @classmethod
    def known_class(cls, v):
        if v not in ALLOWED: raise ValueError(f"asset_class must be one of {sorted(ALLOWED)}")
        return v
    @field_validator("price")
    @classmethod
    def non_negative(cls, v):
        if v < 0: raise ValueError("price must be >= 0")
        return v
class InstrumentOut(InstrumentIn):    # what the API RETURNS (adds id)
    id: int
    model_config = ConfigDict(from_attributes=True)   # can read a DB row directly

# ---- 3. one DB session per request ----
def get_db():
    with Session(engine) as session:
        yield session

# ---- 4. FastAPI: the SERVER ----
app = FastAPI(title="Instrument Reference API", version="1.0")

@app.get("/instruments", response_model=list[InstrumentOut])
def list_instruments(db: Session = Depends(get_db)):
    return db.scalars(select(InstrumentRow)).all()

@app.get("/instruments/{symbol}", response_model=InstrumentOut)
def get_instrument(symbol: str, db: Session = Depends(get_db)):
    row = db.scalar(select(InstrumentRow).where(InstrumentRow.symbol == symbol))
    if row is None:
        raise HTTPException(status_code=404, detail="instrument not found")
    return row

from app import engine, InstrumentRow, Base

from sqlalchemy import select
Base.metadata.create_all(engine)

]
with Session(engine) as s:
    for sym,name,cls,ccy,px in DATA:
        if not s.scalar(select(InstrumentRow).where(InstrumentRow.symbol==sym)):
            s.add(InstrumentRow(symbol=sym,name=name,asset_class=cls,currency=ccy,price=px))
    s.commit(); print("seeded:", s.scalars(select(InstrumentRow.symbol)).all())
1. python seed.py   2. uvicorn app:app --reload
Try it: curl http://127.0.0.1:8000/instruments/AAPL
{"symbol":"AAPL","name":"Apple Inc","asset_class":"equity","currency":"USD","price":195.2,"id":1}
Two new ideas worth namingPath parameter: {symbol} in the URL becomes the function's symbol argument — that's how /instruments/AAPL knows which one. response_model: FastAPI runs your DB rows back through the Pydantic contract on the way out, so the response shape is guaranteed. And HTTPException(404) is how you return a proper "not found" instead of crashing.

POST — a request that sends data

the request has a body · the contract validates it before you touch the DB

Add this to app.py. Now the client can create an instrument by sending JSON.

app.py (add)
@app.post("/instruments", response_model=InstrumentOut, status_code=201)
def create_instrument(payload: InstrumentIn, db: Session = Depends(get_db)):
    exists = db.scalar(select(InstrumentRow).where(InstrumentRow.symbol == payload.symbol))
    if exists:
        raise HTTPException(status_code=409, detail="symbol already exists")
    row = InstrumentRow(**payload.model_dump())   # validated Pydantic -> DB row
    db.add(row); db.commit(); db.refresh(row)
    return row
Create one: curl -X POST http://127.0.0.1:8000/instruments \
  -H "Content-Type: application/json" \
  -d '{"symbol":"BTCUSD","name":"Bitcoin","asset_class":"fx","currency":"USD","price":68000}'
# 201 Created {"symbol":"BTCUSD","name":"Bitcoin","asset_class":"fx","currency":"USD","price":68000.0,"id":6}
The magic line: payload: InstrumentInBecause you typed the argument as your Pydantic model, FastAPI automatically reads the request's JSON body, validates it against the contract, and only calls your function if it passes. Send a bad body and you get a 422 with the exact reasons — you never wrote validation code in the endpoint:
# POST with asset_class:"crypto", price:-1 -> 422 rejected: asset_class - Value error, asset_class must be one of ['bond','commodity','equity','fx'] rejected: price - Value error, price must be >= 0

The client — the other side

write code that CALLS your API · see both halves
client.py
import httpx
BASE = "http://127.0.0.1:8000"

# GET the list
resp = httpx.get(f"{BASE}/instruments")
print("GET /instruments ->", resp.status_code)
for inst in resp.json():
    print(f"   {inst['symbol']:8} {inst['asset_class']:10} {inst['price']}")

# GET one
print("\nGET /instruments/AAPL ->", httpx.get(f"{BASE}/instruments/AAPL").json())

# POST a new one
new = {"symbol":"BTCUSD","name":"Bitcoin","asset_class":"fx","currency":"USD","price":68000.0}
print("\nPOST ->", httpx.post(f"{BASE}/instruments", json=new).status_code)
Server running in one terminal, then: python client.py
GET /instruments -> 200 AAPL equity 195.2 MSFT equity 420.1 UST10Y bond 98.7 EURUSD fx 1.09 GOLD commodity 2400.0 GET /instruments/AAPL -> {'symbol': 'AAPL', ... 'id': 1} POST -> 201
Now you've seen both halveshttpx.get / httpx.post send the request; .status_code and .json() read the response. This is exactly what a catalog UI, another service, or a partner does to your API — and what you do to someone else's.

OpenAPI — the contract, written for you

the payoff · interactive docs you didn't write

With the server running, open http://127.0.0.1:8000/docs in a browser.

What you'll seeAn interactive page listing every endpoint (GET /instruments, GET /instruments/{symbol}, POST /instruments), each with its exact request and response shape — generated automatically from your Pydantic models. There's a "Try it out" button that sends real requests. The machine-readable version lives at /openapi.json.

Why this matters for governance: OpenAPI is the API's published contract. A consumer reads it to know exactly how to call you and what they'll get back — no meeting required. "A data contract is an API, and OpenAPI is how that contract is published" is a line you can now say from experience.

Glossary — the words, now concrete

TermWhat it means (you just used it)
request / responseThe client asks (method + path + optional body); the server answers (status code + body).
GET / POSTThe method. GET reads; POST creates. (Also PUT/PATCH to update, DELETE to remove.)
endpoint / routeA URL + method mapped to a function, via @app.get(...).
path parameterA variable in the URL, like {symbol} → the function's argument.
request bodyJSON sent with a POST; typed as a Pydantic model so it's auto-validated.
status code200 ok · 201 created · 404 not found · 409 conflict · 422 invalid body.
response_modelThe Pydantic shape the response is forced into on the way out.
dependencyDepends(get_db) — FastAPI supplies a fresh DB session to each request.
engine / SessionSQLAlchemy: the DB connection, and your per-unit-of-work workspace.
OpenAPIThe auto-generated, machine-readable contract + docs at /docs.
